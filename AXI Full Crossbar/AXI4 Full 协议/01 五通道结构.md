# 01 五通道结构

AXI4 Full 有五个独立通道。

| 通道                 | 方向              | 作用               | 典型信号                                                                 |
| ------------------ | --------------- | ---------------- | -------------------------------------------------------------------- |
| `AW` Write Address | Master -> Slave | 写地址和写控制信息        | `AWID`, `AWADDR`, `AWLEN`, `AWSIZE`, `AWBURST`, `AWVALID`, `AWREADY` |
| `W` Write Data     | Master -> Slave | 写数据和 byte strobe | `WDATA`, `WSTRB`, `WLAST`, `WVALID`, `WREADY`                        |
| `B` Write Response | Slave -> Master | 写事务完成响应          | `BID`, `BRESP`, `BVALID`, `BREADY`                                   |
| `AR` Read Address  | Master -> Slave | 读地址和读控制信息        | `ARID`, `ARADDR`, `ARLEN`, `ARSIZE`, `ARBURST`, `ARVALID`, `ARREADY` |
| `R` Read Data      | Slave -> Master | 读数据和读响应          | `RID`, `RDATA`, `RRESP`, `RLAST`, `RVALID`, `RREADY`                 |



## 写事务通道结构

![[1.jpg]]

写事务由三类通道组成：

```text
AW：告诉 Slave 要写哪里、写多少、怎么 burst
W ：真正的数据 beat，一个 burst 可能有多个 W beat
B ：Slave 告诉 Master 写事务结果
```

关键点：

- `AW` 和 `W` 是独立通道，不共享 `VALID/READY`。
- `B` 是反向返回的写响应通道。
- `BVALID` 不能随便提前返回，必须等写地址和写数据要求满足。
- AXI4 没有 `WID`，所以不能像 AXI3 那样做 write data interleaving（交叉）。
- AXI4 支持多个 outstanding 写事务，但不同写 burst 的 `W` 数据不能交错发送。因为 `W` 通道没有 `WID`，slave/interconnect 不能靠 `WID` 区分交错的数据 beat。
- AXI4 删除 write data interleaving，是因为它对性能帮助有限，却显著增加 master/interconnect/slave 的设计和验证复杂度；连续写 burst 更简单、更高效，也更符合实际系统实现。

## 读事务通道结构

![[2.jpg]]

读事务更直接：

```text
AR：告诉 Slave 要读哪里、读多少、怎么 burst
R ：Slave 返回数据 beat，同时带 RRESP
```

关键点：

- AXI 没有单独的“读响应通道”。
- 读响应 `RRESP` 跟着每个 `RDATA` beat 一起返回。
- 最后一个读 beat 用 `RLAST` 标出来。
